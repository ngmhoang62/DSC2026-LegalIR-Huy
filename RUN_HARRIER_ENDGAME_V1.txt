2) Before GPU runner: exact files required
------------------------------------------
A. Exact chunk-context used by fine-tune:
   signature MUST be:
     files = 8532
     bytes = 380681028

   Do NOT point the runner at selected-contexts.

B. Checkpoint: choose ONE:

Because the Drive log shows only one epoch, final merged and best epoch should
refer to the same training endpoint. Prefer final_model_merged if already local.

3) Local RTX4050 run
--------------------
Example with merged model:

python run_private_harrier_ft_local_v1.py \
  --repo-root /d/Study/DSC2026/sota \
  --chunk-dir /d/Study/DSC2026/sota/PUT_EXACT_CHUNK_CONTEXT_HERE \
  --merged-model-dir /d/Study/DSC2026/sota/results/from_drive/vietlegal/vietlegal_finetuned/final_model_merged \
  --batch-size 64 \
  --query-batch-size 64

Example with adapter:

python run_private_harrier_ft_local_v1.py \
  --repo-root /d/Study/DSC2026/sota \
  --chunk-dir /d/Study/DSC2026/sota/PUT_EXACT_CHUNK_CONTEXT_HERE \
  --adapter-dir /d/Study/DSC2026/sota/results/from_drive/vietlegal/vietlegal_finetuned/best_adapter \
  --batch-size 64 \
  --query-batch-size 64

The runner automatically halves the batch on CUDA OOM.

Notes
-----
- No private labels are read anywhere.
- No REL_L0 is appended.
- Harrier is allowed to alter only D1 rank #5, and only by promoting an existing
  D1 candidate from ranks 6..TOPN. D1 ranks 1..4 are frozen.
- The CAL gate is contaminated by final full-train Harrier. Treat it as a
  stability/mechanism gate, not as clean generalization evidence.
